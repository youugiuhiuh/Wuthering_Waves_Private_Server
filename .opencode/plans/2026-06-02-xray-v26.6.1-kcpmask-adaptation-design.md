# Xray-core v26.6.1 KcpMask Adaptation Design

**Date:** 2026-06-02
**Status:** Draft
**Scope:** Adapt `rust/tgbot` KcpMask system to Xray-core v26.6.1 finalmask changes

## Background

Xray-core v26.6.1 introduces 6 finalmask-related changes that require adaptation in our tgbot's KCP mask configuration generation:

1. **Salamander packetSize (#6198)** — Gecko (Hysteria v2.9.2) support
2. **XDNS resolver format (#6123)** — AAAA & A record type support, new resolver format
3. **XICMP refactor (#6168)** — New `dgram` and multi-`ips` fields
4. **mkcp-legacy (#6201)** — Unified type replacing mkcp-original, mkcp-aes128gcm, header-dns/wechat/srtp/utp/dtls/wireguard
5. **Realm (#6137)** — New UDP hole-punching mask type
6. **header-custom removed (#6193)** — headerConnMode/headerReadAddrAware interface removed

## Design Decisions

- **Full adaptation scope** — All 6 changes implemented in one pass
- **Remove old types** — MkcpOriginal, MkcpAes128Gcm, HeaderDns, HeaderWechat, HeaderSrtp, HeaderUtp, HeaderDtls, HeaderWireguard, HeaderCustom all removed; replaced by MkcpLegacy
- **New XDNS format only** — No backward compatibility with old `+udp://1.1.1.1` format
- **Remove HeaderCustom** — Interface removed in v26.6.1
- **MkcpLegacy uses `Option<String>` for header** — `None` = XOR(original), `Some("aes")` = AES128GCM, `Some("dns"/"wechat"/"srtp"/"utp"/"dtls"/"wireguard")` = header disguise

## 1. KcpMask Enum Redesign

### Old enum (14 variants → removed 9, modified 3, added 2)

```rust
// REMOVED: MkcpOriginal, MkcpAes128Gcm, HeaderDns, HeaderWechat, 
//          HeaderSrtp, HeaderUtp, HeaderDtls, HeaderWireguard, HeaderCustom
// ADDED: MkcpLegacy, Realm
// MODIFIED: Salamander (packet_size), Xdns (resolver format), Xicmp (dgram, ips)

pub enum KcpMask {
    MkcpLegacy { header: Option<String>, value: Option<String> },
    Noise,
    Salamander { password: String, packet_size: Option<String> },
    Sudoku { password: String },
    Xdns { domains: Vec<String>, resolvers: Vec<String> },
    Xicmp { dgram: bool, ips: Vec<String> },
    Realm { url: String, stun_servers: Vec<String> },
}
```

### MkcpLegacy parameter mapping

| header value | value field | Equivalent old type | JSON output |
|-------------|-------------|-------------------|-------------|
| `None` | `None` | MkcpOriginal | `{"type": "mkcp-legacy"}` |
| `None` | `Some(pwd)` | MkcpAes128Gcm | `{"type": "mkcp-legacy", "settings": {"value": pwd}}` |
| `Some("dns")` | `Some(domain)` | HeaderDns | `{"type": "mkcp-legacy", "settings": {"header": "dns", "value": domain}}` |
| `Some("wechat")` | `None` | HeaderWechat | `{"type": "mkcp-legacy", "settings": {"header": "wechat"}}` |
| `Some("srtp")` | `None` | HeaderSrtp | `{"type": "mkcp-legacy", "settings": {"header": "srtp"}}` |
| `Some("utp")` | `None` | HeaderUtp | `{"type": "mkcp-legacy", "settings": {"header": "utp"}}` |
| `Some("dtls")` | `None` | HeaderDtls | `{"type": "mkcp-legacy", "settings": {"header": "dtls"}}` |
| `Some("wireguard")` | `None` | HeaderWireguard | `{"type": "mkcp-legacy", "settings": {"header": "wireguard"}}` |

### Category selection (4→3 categories)

```

```

### MkcpLegacy encryption sub-options (after selecting enc)

```
🔀 mKCP Original (XOR)    — 无加密，仅FNV1a校验
🔐 mKCP AES-128-GCM       — 认证加密
🌐 mKCP + DNS伪装          — 加密+DNS头部
💬 mKCP + 微信伪装          — 加密+微信头部
🎬 mKCP + SRTP伪装         — 加密+SRTP头部
🔗 mKCP + uTP伪装          — 加密+uTP头部
🔒 mKCP + DTLS伪装         — 加密+DTLS头部
🛡️ mKCP + WireGuard伪装   — 加密+WireGuard头部
```

### New Salamander options

Auto-generated defaults: `packet_size: None`. No additional Bot interaction needed.

### New XICMP options

Auto-generated defaults: `dgram: false`, `ips: []`. No additional Bot interaction needed. Server-side XICMP config uses `{"type": "xicmp"}` without settings.

### New Realm options

**Requires user input** — after selecting Realm, the Bot prompts for:
1. `url` (required) — e.g., `realm://example.com:1234`
2. `stun_servers` (required, pre-filled default: `stun:stun.l.google.com:19302`) — user can add more STUN servers

This changes the current single-button selection flow for Realm: instead of immediately adding via callback code `rl`, the Bot needs a multi-step input similar to how other Telegram bots handle text input (force_reply or conversation state).

## 8. Compatibility Notes

- Old Bot codes (mo, ma, hd, hw, hs, hu, hdt, hwg, hc) will no longer be recognized by `from_code()`. Existing KCP configs generated with old types remain valid Xray JSON, but the Bot will not be able to re-create them with old codes.
- Old XDNS resolver format (`+udp://1.1.1.1`) is replaced by new format (`domain[:method]+udp://server:port`). Existing configs with old format may need manual update if Xray-core v26.6.1 drops support for the old format.
- The `mkcp-legacy` type in Xray JSON is backwards-compatible: old `mkcp-original`, `mkcp-aes128gcm`, `header-*` types still work in Xray-core v26.6.1. Our Bot simply prefers the unified `mkcp-legacy` type going forward.

### Xdns Default Resolver Format Change

Old: `"+udp://1.1.1.1"` → New: `"www.baidu.com+udp://1.1.1.1:53"`

The new XDNS resolver format from v26.6.1 (`#6123`) follows the pattern:
- `domain[:method]+udp://server[:port]`
- Method is optional: `a` (A record only), `aaaa` (AAAA only), or omitted (both)
- Port defaults to 53 if omitted
- Minimal form: `+udp://1.1.1.1:53` (no domain prefix, still valid for default resolution)

### Realm User Input Flow

When user selects Realm (`rl`), the Bot must:
1. Send a message with `force_reply` asking for the Realm URL
2. Wait for user response (realm URL, e.g., `realm://example.com:1234`)
3. Optionally ask for STUN servers (with pre-filled default)
4. Create the `KcpMask::Realm` and add it to the mask stack

This is a new interaction pattern — current masks all use single-callback-code selection without text input.
