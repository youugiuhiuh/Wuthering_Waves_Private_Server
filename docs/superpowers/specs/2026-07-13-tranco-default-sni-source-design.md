# Tranco 默认 SNI 数据源设计

## 背景

`sni_tester` 当前要求通过 `-f` 提供 SNI 文件；`sni_tester_app` 则由用户选择并上传域名文件。两套 Go 后端最终都把文本域名解析为 `[]string` 后交给现有测试引擎。

本次变更让两套程序默认通过 [WangYihang/tranco-go-package](https://github.com/WangYihang/tranco-go-package) 获取 Tranco 榜单，同时保留用户文件作为离线或服务不可用时的回退来源。测试引擎本身不感知数据来源。

依赖必须固定到上游 `main` 的提交 `97d69c6`，不得使用当前仍指向旧版 `v0.0.3` 的 `@latest`。该提交包含本设计依赖的缓存目录、原子下载、HTTP 状态检查、下载错误返回、安静模式和请求超时支持。添加依赖时通过 `go get github.com/WangYihang/tranco-go-package@97d69c6` 让 Go 解析并记录对应伪版本。

## 已确认需求

- 数据源优先级为 Tranco 优先、用户文件回退。
- 日期按 UTC 计算；从当天榜单开始尝试，最多逐日向前回退 7 天。
- 在线 Tranco 不可用时，优先使用上述日期窗口内匹配当前选项的本地缓存。
- Tranco 下载和缓存均不可用时，使用用户提供的域名文件。
- 所有来源均不可用时，不启动测试并返回明确错误。
- 默认榜单规模为 Top 1,000,000，即 Tranco `scale="1000000"`。
- 提供 `fullList` 布尔选项；默认 `false`，开启后使用 `scale="full"`。
- 提供 `includeSubdomains` 布尔选项；默认 `false`。
- 现有 `maxLines` 继续限制实际读取和测试的域名数量，不改变下载规模。

## 方案选择

采用在 `sni_tester` 与 `sni_tester_app/go_engine` 中分别维护同结构解析器的方案。

该方案保持当前两个独立 Go 模块和 Android 交叉编译方式不变。相比抽取共享模块，它不会引入新的模块边界和构建耦合；相比调用外部 `tranco` 命令，它可直接用于 Android 嵌入式 Go 后端。两份实现及测试必须保持镜像一致。

## 架构

新增独立的域名来源解析单元，位于 HTTP/CLI 入口与现有测试引擎之间。该单元接收：

- 当前时间；
- `includeSubdomains`；
- `fullList`；
- `maxLines`；
- 可选用户文件或已上传文本；
- 可写缓存根目录。

该单元返回域名切片、实际使用的数据源和榜单日期。数据源标识为：

- `tranco_download`：本次通过 Tranco 包获得；
- `tranco_cache`：使用当天至 7 天前日期窗口内的有效缓存；
- `user_file`：使用用户文件或上传文本。

Tranco 包的调用被封装在小型加载接口之后；生产实现调用 `tranco.NewTrancoList` 并启用 `tranco.WithQuiet()`，测试实现注入确定性结果。日期由可注入时钟生成，使日期回退无需真实等待或网络访问即可测试。

上游包负责榜单 ID 查询、下载和缓存，但只公开按域名查询排名的 `Rank`，不提供全量域名迭代 API。解析器因此通过 `DefaultFilePath()` 获取上游生成的 CSV 路径，再自行流式读取域名。

## 数据流

### `sni_tester` CLI

- `-f` 从必填参数改为可选回退文件。
- 新增 `--include-subdomains`，默认 `false`。
- 新增 `--full`，默认 `false`。
- 参数解析完成后先调用域名来源解析器，再把其结果传给 `Engine.Run`。
- Tranco 与用户文件均不可用时，打印聚合错误并以非零状态退出。

### `sni_tester_app`

- 设置界面增加“包含子域名”和“下载完整榜单”两个开关，默认关闭。
- 两个值通过现有偏好设置服务持久化。
- `StartParams` 和 `/api/start` JSON 增加 `include_subdomains` 与 `full_list`。
- 用户选择域名文件后仍按现有流程上传，但上传内容只作为回退来源。
- `/api/start` 接收请求后进入 `preparing` 状态并立即返回；Go Web 后端在后台解析最终域名来源，成功后进入 `running` 并调用现有引擎。
- Tranco、缓存和用户文件都失败时，后台任务进入 `error` 状态，通过状态接口和 SSE 报告聚合错误，不进入测试引擎。
- App 接受启动接口的异步成功响应，并在准备期间显示“正在获取 Tranco 榜单”，避免受现有 10 秒 HTTP 客户端超时影响。
- Android 本地后端使用应用文档目录作为 Tranco 缓存根目录；桌面与 CLI 使用用户目录下的 Tranco 缓存。

## 榜单选择算法

1. 根据 `fullList` 选择 `1000000` 或 `full`，根据 `includeSubdomains` 选择对应榜单类型。
2. 以 UTC 日期为准，依次尝试当天至 7 天前的 Tranco 榜单，共最多 8 个日期候选。当天榜单未发布或指定日期不存在时继续尝试较早日期；断网、DNS、连接或请求超时等传输错误则停止在线日期循环，立即进入缓存回退。
3. 上游成功返回后，通过 `DefaultFilePath()` 定位 CSV，并验证其至少含有合法的 `排名,域名` 数据；无效或不完整文件不作为成功结果。
4. 在线获取失败后直接扫描指定缓存目录。由于离线时无法通过 Tranco API 获得榜单 ID，不得依赖 `NewTrancoList` 发现缓存。只接受同一日期窗口内与规模、子域名选项完全匹配的文件，并优先选择最新日期。
5. 缓存仍不可用时，读取用户文件或 App 已上传文本。
6. 读取任一来源时立即应用清洗、空行过滤和 `maxLines`，避免把不需要的完整榜单全部载入内存。
7. 所有候选来源失败时返回包含各阶段原因的错误。

## 缓存与可靠性

- 缓存键必须包含日期、子域名选项和榜单规模，禁止跨选项复用。
- 使用固定上游提交内置的单请求 5 分钟 HTTP 超时，避免无限阻塞；App 在后台完成该过程，不占用启动请求连接。
- 对传输级失败只进行一次在线尝试，不对其余日期重复相同网络故障；仅“日期尚无榜单”类响应触发逐日回退。
- 只接受通过基本 CSV 格式验证的缓存。
- 由本功能产生且确认不完整的临时缓存不得在后续运行中被当作有效榜单。
- 状态或日志记录最终来源、榜单日期和选择参数，方便定位离线回退行为。
- 不记录榜单正文或用户文件内容。

## 错误处理

- 单个日期不存在时继续尝试更早日期；传输级下载失败时立即进入缓存回退。
- 网络失败不会阻止缓存和用户文件回退。
- 用户文件无效时，错误需区分“Tranco 不可用”和“用户回退文件不可用”。
- App API 接受任务后返回异步成功响应；准备失败通过 `error` 状态和 SSE 事件传递，UI 不得错误显示为 `running`。
- CLI 在无可用域名时不创建测试任务。

## 测试与验收

两个 Go 模块分别覆盖以下表驱动测试：

- 当天 Tranco 榜单成功；
- 当天失败后命中较早日期；
- 日期不存在会继续回退，而传输错误会直接停止在线日期循环；
- 网络失败后命中最近的有效缓存；
- 完全离线时无需榜单 ID 也能从缓存文件名发现匹配榜单；
- 损坏缓存被拒绝；
- Tranco 全部失败后使用用户文件；
- 无用户文件时返回错误；
- `fullList=false` 映射 `1000000`，`true` 映射 `full`；
- `includeSubdomains` 默认关闭且正确传递；
- `maxLines` 在读取过程中生效。

CLI 测试验证 `-f` 可选及两个新开关默认关闭。Web 后端测试验证 `preparing → running/done` 和 `preparing → error` 状态转换。Flutter 测试验证开关默认值、偏好持久化、API JSON 字段和异步准备状态展示。

实现完成后的质量门禁：

- 两个 Go 模块执行格式化、完整测试和 `staticcheck`；
- Flutter 执行格式化、静态分析和测试；
- Android/桌面构建路径至少完成与本次参数和 Go 后端集成相关的构建验证。

## 非目标

- 不改变 SNI 测试引擎、TLS 探测或结果存储算法。
- 不合并两个现有 Go 模块。
- 不增加自定义 Tranco 日期、任意榜单规模或第三方数据源 UI。
- 不让用户文件与 Tranco 榜单合并；用户文件仅作为完整回退来源。
