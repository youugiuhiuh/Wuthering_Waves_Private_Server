Rust Telegram Bot 纯结构重构总计划 (无代码版)

核心指导原则：

只移动，不重写：绝对不修改 logic/ 文件夹内的底层业务逻辑，本次仅作“文件搬家”和“管线重新对接”。

渐进式编译：每移动完一个模块，务必执行一次 cargo check，不要等全搬完再检查，防止依赖报错堆积成山。

领域驱动归类：将原本揉在 main.rs 中的指令和交互，按“基础命令、代理工具、安全审计、系统运维、按钮回调”五大领域强制分离。

阶段一：建立新目录骨架 (Scaffolding)

目标：把装配新零件的“收纳盒”提前准备好。

[ ] 1. 在 src/ 目录下新建 handlers/ 文件夹。

[ ] 2. 在 handlers/ 文件夹中创建汇总文件 mod.rs。

[ ] 3. 在 handlers/ 文件夹中创建以下五个领域空文件：

command.rs （用于收纳：基础文字指令）

proxy.rs （用于收纳：Xray、Sing-box、Warp 相关的控制交互）

security.rs （用于收纳：防 火墙、Fail2ban、自毁流程的交互）

system.rs （用于收纳：BBR3、系统升级、定时维护的交互）

callback.rs （用于收纳：所有的 Inline 键盘按钮点击事件）

[ ] 4. 在现有的 src/app/ 目录下新建 lifecycle.rs 文件（用于收纳：机器人启动时需要执行的异步通知和检查）。

阶段二：剥离启动与生命周期通知 (Lifecycle Extraction)

目标：把 main.rs 顶部那些杂七杂八的“升级成功通知”、“重启后校验通知”移走。

[ ] 1. 将原 main.rs 中负责“自更新结果通知”的逻辑整体剪切到 app/lifecycle.rs。

[ ] 2. 将原 main.rs 中负责“BBR3 重启后校验通知”的逻辑剪切到 app/lifecycle.rs。

[ ] 3. 在 app/lifecycle.rs 中封装一个统一的“启动后检查”入口，供 main.rs 在启动时调用一次即可。

[ ] 4. 运行 cargo check，修复可能因剪切导致的模块导入 (use ...) 缺失。

阶段三：按领域拆解指令与交互 (Domain Handler Migration)

目标：将 main.rs 中庞大的指令枚举和长篇大论的匹配逻辑（Match），化整为零塞进第一阶段建好的盒子里。

[ ] 3.1 基础命令迁移 (handlers/command.rs)

提取 /start, /help, /status 等通用指令的解析和回复逻辑。

[ ] 3.2 代理工具迁移 (handlers/proxy.rs)

提取安装/卸载 Reality、Warp、Sing-box 相关的对话步骤和指令调用。

[ ] 3.3 安全审计迁移 (handlers/security.rs)

提取防 火墙开关状态切换、安全监控触发、自毁流程校验等交互代码。

[ ] 3.4 系统运维迁移 (handlers/system.rs)

提取触发面板升级、一键内核更换重启、计划任务设定的指令入口。

[ ] 3.5 按钮回调大一统 (handlers/callback.rs)

把 main.rs 中专门过滤和处理“回调查询 (Callback Query)”的巨大逻辑块完整移入此文件，并拆分成多个独立的小型处理函数。

阶段四：组装路由与 main.rs 终极瘦身 (Routing & Slimming)

目标：让 main.rs 从“万能管家”退化为纯粹的“启动开关”。

[ ] 1. 在 handlers/mod.rs 中，建立一个全局路由树（Dispatcher），把阶段三中写好的五个领域的处理器（Handlers）全部“插”到这个路由树上。

[ ] 2. 将鉴权逻辑（验证 Admin ID 的中间件）直接挂载到这个路由树的最顶层，确保统一拦截，避免遗漏。

[ ] 3. 暴力清理 main.rs：

删除所有已经被搬走的逻辑函数。

删除顶部已经失效的 use 导入语句。

将原先构建复杂 Dispatcher 的几十行代码，替换成只调用 handlers::mod.rs 抛出的路由树进行启动。

阶段五：可见性修复与终期测试 (Visibility Fix & Testing)

目标：解决跨文件夹带来的权限报错，并验证机器人能否正常跑起来。

[ ] 1. 执行 cargo build 进行完整编译。

[ ] 2. 根据编译器的红色报错，将被隐藏的结构体、字段或函数（原本在同一个文件里不需要 pub 的东西）加上 pub 或 pub(crate) 权限。

[ ] 3. 编译通过后启动机器人，进行三项冒烟测试：

给机器人发送 /start 确认能正常通信。

点按任意一个包含多级菜单的 Inline 按钮，确认回调能正常触发。

走一遍“防 火墙配置”或“自毁”这种需要多次对话输入的状态机流，确认状态记忆没有因重构丢失。
